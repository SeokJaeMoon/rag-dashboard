# DocFlow v2 — 업로드 문서 인식 오류 수정 버전

## 핵심 개선 사항

이 버전은 `samples/2026_사내공지사항_샘플.txt` 전용 앱이 아닙니다. **로컬 PC에서 사용자가 직접 선택한 텍스트 파일을 FileReader로 읽고, 실제 내용으로 청크를 만들어 검색**합니다.

1. **인코딩 자동 감지**: UTF-8(BOM 포함), UTF-16 LE/BE(BOM 포함 및 흔한 BOM 없는 파일), CP949(EUC-KR)를 읽습니다. 자동 감지가 잘못되면 업로드 영역의 **텍스트 인코딩**을 직접 선택하고 동일 파일을 다시 업로드하세요.
2. **분석 대상 선택**: 새 텍스트 파일을 업로드하면 그 파일이 **질의응답 분석 대상**으로 자동 지정됩니다. 기존 샘플과 다른 문서가 섞여 있더라도 질문이 새 파일을 우선 사용합니다. 여러 파일을 함께 검색하려면 **전체 등록 문서**를 선택하세요.
3. **업로드 결과 확인**: 파일명, 디코딩 인코딩, 청크 수가 화면에 표시됩니다.
4. **문서 일반 질의 지원**: `이 문서 요약해줘`, `주요 내용은 무엇인가요?`처럼 전체를 묻는 질문은 업로드한 문서의 여러 청크를 **발췌**합니다. 단어 기반 질문에는 업로드한 문서에서 관련 청크를 검색합니다.
5. **문장 발췌 개선**: 짧은 문서는 단락 전체를 표시하여 금액·기한 등의 중요한 정보가 제목만 나오는 문제를 줄입니다.
6. **지원 확장자**: `.txt`, `.md`, `.csv`, `.log`를 텍스트로 검색할 수 있습니다. `.pdf`는 이전 버전과 같이 실제 본문이 아닌 **가상 구조**만 표시하며 검색 대상에 포함하지 않습니다.
7. **동일 파일 재업로드**: 같은 파일명을 다시 업로드하면 이전 청크를 새 내용으로 대체합니다(정원이 찬 경우엔 기존 파일을 먼저 정리해야 합니다).

> **중요**: 이 코드는 **실제 대규모 언어 모델(LLM), 벡터 검색, 의미 기반 RAG 분석이 아닙니다.** 브라우저에서 수행하는 **키워드 검색 + 근거 발췌 + 모의 스트리밍 데모**입니다. AI 생성 답변이 필요하다면 백엔드 API와 모델 연결이 별도로 필요합니다.

## 파일 구성

```text
rag_dashboard_fixed/
├── index.html                        # 레이아웃·드래그 앤 드롭·인코딩·분석 대상 선택 UI
├── style.css                         # 그리드·모바일·다크모드 스타일
├── app.js                            # 인코딩/파싱/500자 청크/문서 선택/로컬 검색/스트리밍
├── samples/
│   ├── 2026_사내공지사항_샘플.txt     # 기존 시범 문서
│   ├── 스마트시티_업로드_테스트.txt   # 신규 파일 인식 검사
│   └── 근무규정_업로드_테스트.txt     # 다른 주제 검사
├── .nojekyll
└── README.md
```

## 크롬에서 바로 실습

1. `index.html`을 크롬에서 실행하거나 GitHub Pages에 게시합니다.
2. **샘플 문서 불러오기 버튼을 누를 필요 없이** 좌측 **파일 업로드**에서 원하는 `.txt`를 선택합니다.
3. 업로드 성공 시 `1개 등록 완료. 파일명 (UTF-8, 3청크)`와 같은 메시지가 나옵니다.
4. **질의응답 분석 대상**에 업로드한 파일명이 자동으로 지정되었는지 확인합니다.
5. 우측에서 `이 문서 요약해줘` 또는 해당 파일에 있는 특정 정보를 질문합니다.
6. 출처 버튼을 클릭하면 **실제 업로드한 파일의 청크**가 좌측에 강조 표시됩니다.
7. 다른 파일을 업로드하면 검색 대상이 새 파일로 전환됩니다. **전체 등록 문서**를 선택하면 모든 등록 텍스트를 함께 검색할 수 있습니다.

### 샘플 실습 (기존 사내공지 샘플이 아닌, 새 문서)

- `samples/스마트시티_업로드_테스트.txt`를 직접 업로드 → `자율주행 차량 운행 시간은?` 또는 `이 문서 요약해줘` 질문
- `samples/근무규정_업로드_테스트.txt`를 직접 업로드 → `출장비 정산은 며칠 이내인가요?` 질문
- Windows 메모장으로 저장한 **ANSI(CP949)** 한글 TXT도 업로드해 봅니다. 글자가 깨지면 `텍스트 인코딩`에서 **CP949 / EUC-KR**를 선택한 다음 재업로드합니다.

### 인코딩이 잘못 해석될 경우

자동 판독은 대부분의 파일에서 동작하지만, 모든 문자 인코딩을 완벽하게 추론할 수는 없습니다. 인코딩을 명시적으로 선택한 후 같은 파일을 다시 업로드하거나 원본을 UTF-8로 저장해 주세요. 암호화 파일·바이너리 파일은 지원하지 않습니다.

## GitHub Pages에 기존 코드 교체

1. ZIP 압축을 해제합니다.
2. GitHub 저장소에서 이전의 `index.html`, `style.css`, `app.js`를 **이 ZIP의 새 파일로 교체**하고, `samples/`의 예제 TXT를 필요하면 추가합니다.
3. **Commit changes**를 누릅니다.
4. `Settings → Pages`가 이미 설정되어 있다면 재설정은 필요하지 않습니다. 기존 공개 주소를 다시 엽니다.
5. Chrome에서 **Ctrl+Shift+R** (Mac: **Cmd+Shift+R**)로 강력 새로고침합니다. HTML에서 참조하는 정적 파일 주소에 `?v=2.0`이 붙어 있어 캐시 갱신에도 도움이 됩니다.

처음 공개하는 경우 GitHub 저장소의 **Settings → Pages → Deploy from a branch → main → /(root)** 를 선택해 저장합니다.

## 설계와 제한

- HTML5 시맨틱 구조 (`header`, `nav`, `aside`, `main`, `section`, `article`, `footer`)
- 브라우저 FileReader (ArrayBuffer), TextDecoder, Drag and Drop, 로컬 상태 (`AppStore`)
- `DocumentService`: 실제 텍스트 본문 읽기·목차 추출·500자 청크 생성/60자 중첩
- `LocalRetriever`: 질문의 단어를 청크 내용·제목과 비교해 순위화, 넓은 질문은 원문을 발췌
- `RagApiClient`: `POST /api/rag-query`와 같은 인터페이스를 제공하지만 실제 요청 대신 모의 `Response`/`ReadableStream`를 이용
- `StreamTypewriter`: `requestAnimationFrame()`으로 점진적으로 출력하고 `AbortController`로 중단
- `DocumentView`와 `ChatView`: DOM 생성 시 `textContent` 사용, 채팅 접근성 `aria-live` 상태 유지
- 파일 수 최대 **8개**, 텍스트 및 PDF 각 **2MiB**. 파일 텍스트는 브라우저 메모리에서만 처리합니다.
- 사용자가 업로드한 파일은 **GitHub 저장소에 게시되지 않고** 본인 브라우저에서 처리됩니다.
- 실제 PDF 내용 분석에는 별도 PDF 파서(예: PDF.js) 또는 백엔드가 필요합니다.
- 메모리 상의 문서 상태는 새로고침 시 초기화됩니다. 다크모드 선호만 로컬 저장할 수 있습니다.

## 실제 백엔드 연결 참고

`app.js`의 `CONFIG.DEMO_MODE = false`로 바꾸고 실제 API 엔드포인트(HTTPS)를 설정하면 NDJSON 스트리밍 처리 부분을 재활용할 수 있습니다. 현재 모의 API 페이로드는 아래 형식입니다.

```json
{"question":"출장비 정산 기한은?","retrieval":{"mode":"search","documents":["규정.txt"],"words":["출장비","정산","기한"],"context":[{"documentName":"규정.txt","sectionTitle":"본문","text":"..."}]}}
```

실제 서버 연결 시 문서 접근 제어·CORS·인증·서버 측 검증·개인정보보호와 전송 암호화를 구현하고 API 키를 프론트엔드에 하드코딩하지 마세요.

**주의:** 이 데모는 사용자 파일 내용을 서버로 보내지 않습니다. 단, **사내 기밀문서 자체를 공개 GitHub 저장소에 올리지 마세요.** GitHub Pages에 코드만 배포하고 문서는 실행하는 사용자 브라우저에서 별도 업로드해야 합니다.

## 브라우저 검증

독립 실행된 Chromium에서 HTML/CSS/JS를 로드하여 다음을 검사했습니다.

- UTF-8 사용자 텍스트 업로드 및 해당 문서 내용으로 검색 성공
- CP949 Windows ANSI 한글 TXT 자동 해독 및 급여 지급 날짜 발췌
- UTF-16 LE 한글 TXT의 목차/내용 인식 및 요약형 질문
- 여러 문서 등록 시 **최신 업로드 파일 자동 선택**, `전체 등록 문서` 전환
- 같은 파일명 재업로드 시 청크가 중복되지 않음
- Markdown 업로드, 비텍스트 파일 오류 안내
- 긴 파일 청크 분할, 모바일 가로 넘침 없음
- 개발자 콘솔 JavaScript 오류 없음

정적 파일로 구성되어 있어 GitHub Pages에는 그대로 올릴 수 있으나, 이번 검증에는 실제 GitHub Pages 공개 배포는 포함하지 않았습니다.
